# После встречи

Самостоятельное локальное приложение для расшифровки записей Zoom и Яндекс Телемоста. Выберите способ распознавания **«Локально» / «Онлайн»** и файл WebM или MP4 — сервер извлечёт звук, распознает русскую речь и создаст конспект с четырьмя разделами. Встречи сохраняются на диске и доступны после обновления страницы и перезапуска. Конспект в обоих режимах создаётся через OpenAI.

Использованы Node.js 24+, браузерный JavaScript, HTML/CSS и FFmpeg. У приложения нет npm-зависимостей времени выполнения и сборки. `playwright-core` нужен только для браузерных проверок.

## Возможности

- Локальное распознавание русской речи через GigaAM v3 или онлайн через OpenAI.
- Таймкоды и автоматическое разделение голосов на спикеров.
- Три этапа: загрузка → транскрибация → конспект, с ручным и автоматическим запуском.
- Конспект: краткое содержание, решения, задачи и открытые вопросы.
- Читаемый TXT, сохранение встреч на диске, удаление исходного видео или всей встречи.
- Отдельный журнал токенов и расчётной стоимости API.

В репозитории находятся только исходный код, настройки-примеры и документация. Записи встреч, ключи, журналы, веса моделей и Python-окружение не включены. Это локальный сервер, а не приложение для GitHub Pages.

## Быстрый запуск в Windows

1. Установите Git, Node.js 24 или новее, Python 3.11 (64-bit) и FFmpeg с FFprobe. После установки откройте новый терминал.
2. Проверьте `git --version`, `node --version`, `python --version`, `ffmpeg -version` и `ffprobe -version`.
3. В PowerShell клонируйте проект и перейдите в его папку:

```powershell
git clone https://github.com/atssvetl/meeting-notes.git
cd meeting-notes
Copy-Item .env.example .env
```

4. Откройте `.env` в редакторе и задайте `OPENAI_API_KEY` для конспекта и онлайн-распознавания. Локальная расшифровка не требует ключа. Нужен действующий ключ проекта OpenAI API, доступ к выбранным моделям и средства/квота API. Не отправляйте ключ в чат и не добавляйте его в Git.
5. Установите локальные модели командой `npm run setup:local` (нужен Python 3.11). Определение спикеров работает локально в обоих режимах. Затем запустите:

```powershell
npm start
```

6. Откройте **http://127.0.0.1:3030**. Для обычного запуска `npm install` не требуется. Пока терминал с сервером работает, обработка продолжается независимо от вкладки. Закрывать страницу во время передачи самого файла нельзя; после окончания передачи обработка продолжится на сервере.

На Linux/macOS установите Node.js 24+, Python 3.11 с поддержкой venv/pip и FFmpeg средствами ОС. После клонирования выполните `cp .env.example .env`, затем `python3.11 scripts/install-local.py` и `npm start`. Скрипты `setup:local` и `setup:diarization` используют команду `python`; если её нет, вызывайте соответствующий `.py` через `python3.11`. Проверки проекта выполнены на Windows; Linux/macOS отдельно не проверялись.

`.env` копируйте только при первой установке, чтобы не затереть существующие настройки. Для обновления остановите сервер через Ctrl+C, выполните `git pull --ff-only` и снова `npm start`. При изменении зависимостей разработки выполните `npm ci`, при изменении установщика моделей — `npm run setup:local`.

## Локальное распознавание русского языка

Установщик использует модель [sherpa-onnx GigaAM v3 с пунктуацией](https://huggingface.co/csukuangfj/sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16), ревизия `a6039be7cee829a9044a69ac0ebaf1c191217c97`. После установки веса ONNX находятся в `models/sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16/`, отдельное Python-окружение — `.venv-local/`. Файлы модели занимают около 232 МБ; окружению и моделям разделения голосов также нужно место. Лицензия GigaAM скачивается в `models/.../LICENSE`. У сторонних моделей и инструментов действуют собственные лицензии; ссылки на источники закреплены в установщиках.

Для повторной установки или переноса на другой компьютер нужен Python 3.11 (проверенная версия, 64-bit):

```powershell
npm run setup:local
```

Установщик создаёт отдельное окружение, ставит зависимости из `requirements-local.txt`, скачивает закреплённую версию и проверяет размер и контрольные суммы каждого файла. Уже скачанные корректные файлы переиспользуются. Удалённые Python-скрипты из репозитория модели не исполняются. Интернет требуется для установки; само распознавание работает без сети на CPU. CUDA/PyTorch не нужны.

После установки перезапустите `npm start`. Над загрузкой появится переключатель:

- **Локально** — GigaAM v3 распознаёт аудио на компьютере, за распознавание API-платы нет. В OpenAI отправляется только текст для конспекта.
- **Онлайн** — аудио распознаётся через OpenAI, затем там же создаётся конспект. Оба этапа оплачиваются по тарифам API.

При первом открытии выбирается локальный режим, если модель установлена. Последующий выбор сохраняется в браузере. Способ транскрибации можно изменить в карточке до её выполнения. Файл разрешается загрузить и до установки модели; локальная транскрибация потребует установленной модели. Переключение в облако автоматически не выполняется.

Без ключа локальная расшифровка сохраняется и доступна в блоке «Полная расшифровка». Отключите автозапуск конспекта, чтобы завершить работу на этом этапе без ошибки. Если запустить конспект без ключа, ошибку получит только этот этап. Это не полностью офлайн-конспектирование. При наличии ключа текст отправляется в OpenAI при ручном или автоматическом запуске конспекта.

Сначала на всей записи определяются участки речи и голоса. Затем речевые участки разбиваются на фрагменты до 25 секунд с выбором тихой границы между 15 и 25 секундами. На границах возможны ошибки слов и пунктуации; речь, пропущенная детектором, может не попасть в текст. Скорость зависит от CPU. По умолчанию используются 2 потока; `LOCAL_THREADS` задаёт от 1 до 16. Максимальное время одного локального запуска — 30 минут. После завершения процесс модели освобождает память.

Настройки `LOCAL_PYTHON` (полный путь к Python окружения), `LOCAL_MODEL_DIR` (каталог весов), `DIARIZATION_MODEL_DIR` (модели спикеров) необязательны; стандартные пути определяются автоматически. Локальные операции отражаются в `usage.jsonl` как `provider: "local"`, с длительностью, временем работы и стоимостью API `$0`; токены API для них неприменимы. Электричество/стоимость оборудования не учитываются. `npm run usage` отдельно считает локальные операции и запросы API.

Проверка на ваших реальных видео, без внешних запросов и платы API:

```powershell
npm run test:local -- "C:\Videos\встреча.mp4" "C:\Videos\встреча.webm"
```

Тест использует отдельный каталог и пустой API-ключ, проверяет настоящую расшифровку, её сохранение и очистку аудио. Отчёт и тексты сохраняются в `test-output/`. В `npm test` также есть проверка на настоящем WAV из репозитория модели; без установленной модели она помечается пропущенной.

## Этапы обработки и удаление

### Таймкоды и спикеры

Новые расшифровки содержат реплики вида **`[00:01:12.340 – 00:01:18.720] Спикер 2`**. Они отображаются в карточке встречи и TXT. В JSON поле `transcriptSegments` хранит `start`/`end` в секундах от начала исходной записи, номер `speaker` и `text`; `transcript` содержит тот же текст без разметки для конспекта. Тишина и границы пятиминутных WAV не сбрасывают время и нумерацию спикеров.

Голоса разделяются локально через [sherpa-onnx Offline Speaker Diarization](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html): pyannote segmentation 3.0 и WeSpeaker ResNet34. Модели скачиваются из официальных релизов sherpa-onnx с проверкой SHA-256 в `models/diarization/`; загрузка составляет около 34 МБ. `npm run setup:local` включает их установку. Если GigaAM и окружение уже установлены, достаточно `npm run setup:diarization`, затем перезапустить сервер.

**Спикер 1, 2, … — условные номера голосов в порядке первого появления, а не имена участников.** Таймкоды обозначают приблизительные границы реплик, не отдельных слов. Число голосов определяется автоматически; похожие голоса, шум и одновременная речь могут приводить к ошибкам. Пересекающиеся интервалы возможны при одновременной речи.

В локальном режиме реплики распознаёт GigaAM. В онлайн-режиме разделение голосов также выполняется на компьютере, затем каждый речевой фрагмент отправляется в OpenAI отдельно. Поэтому даже для онлайн-режима нужны Python, sherpa-onnx и модели разделения голосов. Платных запросов может быть больше, чем раньше; каждый отражается в журнале расходов. Локальное разделение голосов учитывается отдельной бесплатной операцией `diarization`.

Для ранее созданной встречи раскройте «Полная расшифровка» и нажмите **«Добавить таймкоды и спикеров»**. Нужны сохранённое исходное видео и установленные локальные модели. Выполняется повторное локальное распознавание, поэтому формулировки могут отличаться. Прежний текст сохраняется в JSON в поле `transcriptBeforeDiarization`; готовый конспект остаётся от предыдущей расшифровки, без повторного обращения к API. При ошибке прежний текст остаётся доступен. Если исходное видео удалено, загрузите запись заново.

Также можно остановить сервер через Ctrl+C и выполнить:

```powershell
npm run annotate -- <идентификатор-встречи>
```

Команда обновляет JSON и TXT указанной встречи, соблюдает блокировку каталога и не вызывает платный API.

### Читаемый текст встречи

После транскрибации рядом с `data/meetings/<uuid>.json` автоматически создаётся **`data/meetings/<uuid>.txt`** в UTF-8. Его можно открыть в Блокноте или редакторе: имя записи, дата, полная расшифровка с абзацами и переносами строк, затем конспект с четырьмя разделами. Слова расшифровки не переписываются, меняется только форматирование. После создания конспекта TXT обновляется. Пока конспекта нет, это явно указано в файле.

В раскрытой карточке есть ссылка **«Скачать текст встречи (.txt)»**. При удалении только видео TXT остаётся; при удалении встречи удаляются её JSON и серверный TXT. Копии, уже скачанные в папку загрузок браузера, остаются у пользователя.

Старые записи экспортируются при следующем запуске сервера. Создать TXT для уже сохранённых встреч без перезапуска можно командой `npm run export:text` из папки приложения. Команда читает JSON и создаёт только TXT, не запускает AI и не расходует API-квоту. TXT является автоматически обновляемой копией: для собственных правок сохраните файл под другим именем.

### Управление этапами

Обработка состоит из трёх независимых этапов:

1. **Загрузка файла** — выбор файла запускает передачу и проверку контейнера/дорожек. Результат: «Файл загружен» или «Ошибка». Видео сохраняется на диске.
2. **Транскрибация** — «Авто» запускает её после загрузки; без флажка используется кнопка «Запустить». Доступны локальное и онлайн-распознавание. При ошибке можно повторить этот этап по сохранённому видео.
3. **Конспект** — «Авто» запускает его после успешной транскрибации; без флажка он запускается кнопкой. Повтор после ошибки использует уже сохранённый текст и не расходует ресурсы на повторную транскрибацию.

Флажки над загрузкой задают настройки новой записи и запоминаются в браузере. В карточке их можно изменить отдельно для каждой встречи. Включение «Авто» у ожидающего этапа начинает его, если входные данные уже готовы. Ошибочный этап автоматически не повторяется: для него нужна кнопка «Повторить». Завершённый этап нельзя запустить ещё раз. По умолчанию оба флажка включены, как в исходном автоматическом сценарии.

Обновление страницы и перезапуск сервера сохраняют ожидающие этапы, настройки и видео. Прерванный этап помечается ошибкой; после запуска сервера его можно повторить вручную. Одновременно выполняется одна операция. Пока она выполняется, изменение настроек и удаление заблокированы.

В карточке доступны два действия с подтверждением:

- **Удалить файл** — удаляет только исходное видео с диска сервера; расшифровка, конспект и карточка остаются. После этого невыполненную транскрибацию запустить нельзя; конспект по сохранённому тексту доступен.
- **Удалить встречу** — удаляет видео, временные файлы, расшифровку, конспект и карточку. Журнал токенов и расходов сохраняется независимо.

Оригинальный файл на вашем компьютере, выбранный через браузер, не затрагивается. Удаляется только его серверная копия. Для старых встреч, созданных до этой доработки, видео уже удалено прежней версией приложения; восстановить его нельзя, но сохранённый текст можно использовать для конспекта.

### Команды проекта

Все команды выполняются в папке с `package.json`.

| Команда | Назначение |
| --- | --- |

| `npm run setup:local` | Установить Python-окружение, GigaAM и модели спикеров |
| `npm run setup:diarization` | Установить только модели спикеров в готовое окружение |

Для путей с пробелами в `.env` используйте кавычки. При изменении `.env` перезапустите сервер. Переменные, заданные в окружении процесса, имеют приоритет над `.env`. В браузер ключ не передаётся. Без ключа доступны интерфейс, сохранённые записи и локальная расшифровка; онлайн-распознавание и генерация конспекта завершатся понятной ошибкой, без выдуманного результата.

Используются реальные HTTP-запросы к OpenAI: [распознавание файлов](https://developers.openai.com/api/docs/guides/speech-to-text) и [структурированные ответы](https://developers.openai.com/api/docs/guides/structured-outputs). Для `gpt-transcribe` передаётся `languages[]=ru`; для других совместимых моделей используется `language=ru`. Доступность выбранных моделей зависит от вашего API-проекта.

## Данные и обработка

- Вход: MP4/WebM, максимум **1 ГБ (1 073 741 824 байта)** и **30 минут**. Основной сценарий — 2–5 минут. Нужны видео- и аудиодорожка. Формат и дорожки проверяет FFprobe, звук действительно декодирует FFmpeg; одного расширения недостаточно.
- Загрузка передаётся потоком на диск. Одновременно принимается и обрабатывается только одна запись, в том числе между несколькими вкладками. При обновлении страницы выполняется только чтение текущего состояния.
- Аудио извлекается в моно PCM WAV, 16 кГц, фрагментами по 5 минут (около 9,6 МБ каждый). Для определения спикеров они объединяются в памяти (около 115 МБ отсчётов для 30 минут, дополнительно к памяти моделей), затем распознаются речевые фрагменты. Полная расшифровка передаётся модели конспекта.
- **Онлайн: аудио и расшифровка отправляются внешнему провайдеру OpenAI через интернет. Локально: отправляется только расшифровка для конспекта.** Исходное видео туда не отправляется. Ответы Responses API запрашиваются с `store:false`; это не обещание отсутствия всех видов хранения у провайдера. Действуют условия вашего API-проекта. Локальный запуск не означает офлайн-конспектирование.
- Результаты лежат в `data/meetings/<uuid>.json`. Сначала записывается временный JSON и выполняется `fsync`, затем атомарное переименование. Пользовательское имя файла — только метаданные.
- Исходное видео лежит в `data/sources/<uuid>/` и хранится до явного удаления пользователем. Следите за свободным местом: каждый файл может занимать до 1 ГБ. Непринятые/оборванные загрузки удаляются. Временные WAV лежат в `data/temp/<uuid>/` и очищаются после обработки, а при аварии — при следующем запуске. Незавершённый этап получает состояние «Ошибка».
- `data/server.lock` не даёт двум процессам одновременно использовать один каталог. Блокировка умершего процесса снимается при запуске. Каталог `DATA_DIR` должен быть выделен только этому приложению.
- Расшифровка сохраняется до запроса конспекта. Если генерация не удалась, её можно раскрыть в записи с ошибкой и повторить только создание конспекта. Повторная загрузка нужна лишь если исходный файл отсутствует и требуется транскрибация.
- Конспект проверяется на обязательные поля и типы. Пустые разделы отображаются как «Не зафиксированы»; неизвестные исполнитель и срок — «не указан». Текст вставляется через `textContent`, HTML из записи не исполняется.
- Сервер слушает только `127.0.0.1`, проверяет Host и Origin, не открывает каталог данных или `.env` через HTTP. Авторизации нет: приложение предназначено для личного локального использования.

## Проверки

```powershell
npm ci
npm test
npm run test:ui
```

Для `test:ui` нужен установленный Chrome/Edge/Chromium. Если программа не найдена автоматически, задайте `BROWSER_PATH`. Скриншоты записываются в `test-output/`. Без моделей часть локальных тестов пропускается. Браузерный сценарий с настоящей речью дополнительно требует собственную двухминутную запись по пути `test-output/real-2min.mp4`; она не поставляется в репозитории. Тесты используют отдельные временные каталоги, не меняют `data/` и не вызывают платный API. Для проверки распознавания используется настоящее аудио, а искусственные данные — только для проверки ошибок, форматирования, структуры и расчётов.

Для проверки собственных реальных записей длительностью 2–5 минут:

С ключом из `.env` эта команда действительно отправляет аудио и текст в OpenAI и расходует API-квоту. Содержательное соответствие решений, задач, исполнителей и сроков записи нужно проверить вручную. Без ключа команда проверяет только путь до распознавания и честно фиксирует ограничение.

## Журнал токенов и стоимости

Расход записывается отдельно от технических сообщений в два файла: `data/usage.jsonl` — данные для анализа, `data/usage.log` — читаемый текстовый лог. При заданном `DATA_DIR` файлы лежат в нём. В обычный терминал сервера расходы больше не выводятся, а в новых JSON встреч не дублируются. Новые операции дописываются в журналы; прежние записи `usage.jsonl` продолжают учитываться. Из старых конспектов неизвестные расходы восстановить нельзя.

Внизу приложения есть отдельный раскрываемый **«Журнал токенов и расходов»**: итоги за всё время, последние 100 операций и скачивание полного JSONL. Для каждого запроса отображаются модель, этап, входные/кешированные/выходные/суммарные токены и расчётная стоимость. Отсутствующие сведения обозначены «?»/«Неизвестно», локальные токены — «Не используются». Удаление встречи не изменяет журнал.

Общий расход за всё время и итоги по каждой встрече:

```powershell
npm run usage
```

Смотреть новые строки журнала в реальном времени (PowerShell, стандартный каталог данных):

```powershell
Get-Content .\data\usage.log -Encoding UTF8 -Wait -Tail 10
```

Журнал содержит дату, идентификаторы встречи и запроса, модель, операцию, статус HTTP, входные/кешированные/выходные/суммарные токены, длительность аудио, расчётную стоимость в USD и использованные тарифы. Текст записи, ключи и содержимое ответов в этот журнал не попадают. При нескольких аудиофрагментах каждый запрос учитывается отдельно. Расход учитывается и при отказе/незавершённом ответе модели, если API вернул `usage`.

Тарифы находятся в `pricing.json`; после их изменения перезапустите сервер. Уже записанные расходы не пересчитываются. Проверено 08.11.2026: [gpt-transcribe](https://developers.openai.com/api/docs/models/gpt-transcribe) — $0.0045 за минуту; [gpt-4.1-mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) — $0.40 за миллион входных, $0.10 за миллион кешированных входных и $1.60 за миллион выходных токенов. Для другой модели добавьте её точное имя и соответствующие тарифы в `pricing.json`; иначе стоимость будет неизвестна.

Для аудиомодели количество токенов может отсутствовать: тогда записывается `null`, а стоимость рассчитывается по длительности из API, либо по измеренной длительности отправленного WAV с отметкой `local_audio_duration`. Токены не оцениваются по длине текста. Неизвестные расходы и запросы без токенов показываются отдельными счётчиками; сумма охватывает только известные значения. При отсутствии сведений о кеше текстовые входные токены оцениваются по обычной ставке.

**Стоимость расчётная, а не подтверждённое списание.** Сверяйте фактические платежи с биллингом OpenAI: возможны скидки, налоги и изменения тарифов. При сетевом сбое или HTTP-ошибке стоимость запроса неизвестна, а не равна нулю. При аварийном завершении до получения ответа или недоступности диска журнал может быть неполным; такие расходы проверяйте в кабинете провайдера. Это локальный журнал приложения, не история всего API-аккаунта.

## Ограничения

### Частые проблемы

- **`ENOENT ... package.json`**: терминал открыт не в папке приложения. Перейдите в `meeting-notes` и повторите `npm start`.
- **«Этот каталог данных уже использует другой процесс»**: сервер уже работает. Откройте его страницу или остановите прежний сервер через Ctrl+C в его терминале. В Windows PID указан в `data/server.lock`: проверьте его через `Get-Process -Id <PID>`, затем при необходимости остановите именно этот процесс через `Stop-Process -Id <PID>`. Удалять блокировку работающего сервера нельзя; блокировка завершившегося процесса снимается автоматически при запуске.
- **`EADDRINUSE`**: порт занят. Остановите прежний сервер или измените `PORT` в `.env`.
- **Локальная модель недоступна**: выполните `npm run setup:local`, проверьте Python и пути в `.env`, перезапустите сервер. Модели голосов нужны и для онлайн-расшифровки.
- **FFmpeg/FFprobe не найдены**: добавьте программы в PATH или задайте их полные пути в `.env`.
- **Нет API-ключа**: локальная транскрибация доступна. Отключите «Авто» у конспекта; для онлайн-операций задайте ключ и перезапустите сервер.

### Точность и хранение

Распознавание, определение спикеров и конспект могут содержать ошибки модели; схема гарантирует структуру, а не фактическую точность. Очень тихая запись (пиковый уровень не выше −55 dB) считается тишиной. Разделение на фрагменты может повлиять на слова у границ реплик. Нет автоматического повтора платных запросов, авторизации и публикации в интернете. Повреждение отдельных JSON фиксируется в журнале; такой файл пропускается при чтении. Для резервной копии остановите приложение и скопируйте `data/meetings/`, `data/sources/` и файлы журналов расходов.

Технический журнал выводится в терминал: идентификатор операции, тип/код ошибки и HTTP-статус провайдера. Секреты, расшифровки и необработанные ответы провайдера не журналируются. При ошибке диска новые загрузки блокируются до исправления причины и перезапуска сервера.
